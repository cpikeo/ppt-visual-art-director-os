# 人工验收集（Visual Acceptance Kit）

**为什么是人工签**：判断建议正确（bench/unseen 已证一部分）、页面结构安全（verify 硬门
已证）与**真实作品具有专业视觉质量**是三件不同的事。第三件只有在目标软件里用眼睛
过完 6 个维度才算数——`ghost` 预览与自检结果**不得**充当视觉验收签字依据（它们只证明
结构与判断，不证明观感）。本目录不引入任何渲染引擎依赖；签字动作发生在 PowerPoint
（或 Keynote/WPS）里。

当前状态：**视觉初审已完成**（[初审记录-2026-10-15](初审记录-2026-10-15.md)：
A 26/30 · B 24/30 · 红线 0 · 均有条件通过）；P1 最小视觉修订已执行并留档；
**修订后复核与目标软件终签待补＝未发布**（状态机见 `验收单.md`）。

## 签字流程（每份 ≤15 分钟）

1. 在 PowerPoint 打开 PPTX（目标软件即验收环境；不要看 ghost PNG 签字）。
2. 按 6 维度过一遍（每维度 1–5 分＋一句话依据）；红线项任一触发＝整份退回。
3. 在 `验收单.md` 对应行填分、签名、日期。**机器预填的结构事实只是导航，不是分数。**

## 六维度（评什么）

| 维度 | 1 问（不达 3 分即退回） |
|---|---|
| 设计概念 | 整套的视觉世界与内容气质一致吗？两套样品的差异是内容使然还是模板使然？ |
| 视觉中心 | 每页第一眼落在主张/证据的主语上吗？有没有第二焦点抢读？ |
| 空间秩序 | 留白说得出处吗？对齐线是否成轴？有没有无理由的空洞或挤压？ |
| 中文排版 | 断行在语义停顿上吗？数字与单位同行吗？标点悬挂/避头尾对吗？行长可读吗？ |
| 跨页节奏 | 疏密交替有呼吸吗？连续同构图是内容需要还是偷懒？开场与收束立得住吗？ |
| 图片与图表 | 图表是否一眼可读（直接标注、单点高亮）？有图页的图是主语/证词还是装饰？（无图页此维度记 N/A） |

## 红线（任一触发＝退回，不看总分）

- 断行把数字与单位拆开，或把动词与对象拆开（“数字不与单位拆行”）
- 标题结论与页内证据对不上（主张错位出现在作品里）
- 有来源/口径的数据没有出处可见
- 图表要求读者心算（双饼、雷达、等权卡片墙）
- 文字溢出文本框、被裁切、压到图片主体
- 中西文标点混用成明显错误（中文句子里的半角逗号连排等）

## 边界（谁签什么）

- 本单只签**视觉质量**。判断正确性由 `scripts/bench.py`（57 例回归）与
  `scripts/unseen_bench.py`（泛化）负责，结构安全由 `verify` 硬门负责，互不冒充。
- 未签＝未验收。任何「已通过视觉验收」的宣称必须带本单的签名行。
- **状态字段是发布门**（见 `验收单.md`）：视觉初审 → 修订后复核 → P0 目标软件终签 →
  可发布。manifest 的 `target_powerpoint=not_verified` 是如实的未验证状态，**不是**
  通过；通过与否只认验收单状态字段。

## 系统化规则（P2 · 2026-10-15 视觉初审后固化）

1. **目标软件终签是真实状态字段**：不把 not_verified 当通过；未终签＝未发布。
2. **两种视觉世界是对照资产**：deck-A 证明中性纸面编辑体，deck-B 证明暗色调度台；
   不把 B 简化成 A 的换色版（B 保留工作台式构图、数据场节奏与暗场语境约束）。
3. **评分永不合并**：每份真实成品沿用六维度＋红线；不与 verify/bench/unseen 汇成
   单一总分——四个门证明四件不同的事。
4. **变更纪律**：改文字主张/数据口径→新一轮 holdout 复验（泛化期望冻结哈希不许动）；
   纯视觉微调→至少 release strict＋PowerPoint 目检＋验收单复核。
5. **视觉判断不倒灌语义规则**：视觉验收意见只修 build 层（几何/层级/强调），
   不进 intelligence 的判断规则；F1–F3 不因视觉验收自动修改，F4–F6 不因视觉签字
   被当作主张边界裁定。
